# pm25_components__raster2polygon

Code to produce spatial aggregations of PM2.5 **component** estimates as generated by the [Atmospheric Composition Analysis Group](https://sites.wustl.edu/acag/datasets/surface-pm2-5/). The spatial aggregations are performed for satellite PM2.5 components from grid/raster (NetCDF) to polygons (shp).

The pipeline supports two algorithm versions (**V5NA** and **V6NA**) as separate data sources, selected via configuration. **V6NA is the current default.** Data for each version is stored in isolated directory trees to prevent cross-contamination.

---

# Washington University PM2.5 Components

The [Atmospheric Composition Analysis Group](https://sites.wustl.edu/acag/datasets/surface-pm2-5/) uses a combination of satellite images, monitors and simulation to generate estimates of PM2.5 and its chemical components. Estimates are stored in NetCDF files and made publicly available. There are several versions of the estimates.

## V5NA (V5.NA.05.02)

The version [V5.NA.05.02](https://sites.wustl.edu/acag/datasets/surface-pm2-5/) consists of mean PM2.5 component concentrations (μg/m³) available at:

*  Temporal frequency: Annual and monthly
*  Grid resolution: High resolution for North America
*  Geographic region: North America only
*  Components (8): NO3, SO4, Sea Salt (SS), NH4, Dust, Black Carbon (BC), Organic Matter (OM), and Organic Matter with H2O (OM_H2O)

The file name convention varies by component, for example:
* NO3: `V5NA05.02.HybridNO3-NO3.NorthAmerica.yyyyjjj-yyyyjjj.nc`
* SO4: `V5NA05.02.HybridSO4-SO4.NorthAmerica.yyyyjjj-yyyyjjj.nc`
* BC: `V5NA05.02.HybridBC-BC.NorthAmerica.yyyyjjj-yyyyjjj.nc`

Where `yyyy` represents the year and `jjj` represents the Julian day. Annual files span day 001–365 (or 366); monthly files additionally include a 3-letter month abbreviation (e.g. `JAN`, `FEB`) in the filename.

## V6NA (V6.NA.01)

The version [V6.NA.01](https://www.satpm.org/v6-na-01) provides updated component estimates using CNN-based algorithms:

*  Temporal frequency: Annual and monthly
*  Geographic region: North America only
*  Components (7): NO3, SO4, Sea Salt (SS), NH4, Dust, Black Carbon (BC), Organic Matter (OM)

> **Note**: V6NA does not include OM_H2O. If you need OM_H2O, use V5NA.

The file name convention is:
* `V6NA01.CNNPM25.{COMPONENT}.yyyymm-yyyymm.nc`
* Annual example: `V6NA01.CNNPM25.NO3.200001-200012.nc`
* Monthly example: `V6NA01.CNNPM25.NO3.200101-200101.nc`

Monthly files are stored in year subfolders: `monthly/{COMPONENT}/{year}/file.nc`

# Codebook

## Dataset Columns:

The output parquet files contain PM2.5 component concentrations aggregated to geographic polygons. Each file includes:

* **Spatial identifier**: `county` or `zcta` — Geographic unit identifier
* **year**: Year of the data
* **month**: Month of the data (monthly files only)
* **Component concentrations** (μg/m³):
  - `bc`: Black carbon
  - `dust`: Dust
  - `nh4`: Ammonium
  - `no3`: Nitrate
  - `om`: Organic matter
  - `om_h2o`: Organic matter with water (V5NA only)
  - `so4`: Sulfate
  - `ss`: Sea salt

Columns are sorted alphabetically after the spatial/temporal identifiers. Output files are in Parquet format.

# Pipeline Steps

The pipeline runs in four steps:

1. **Download shapefiles** (`src/download_shapefile.py`) — downloads Census boundary files for the chosen polygon type and year
2. **Download components** (`src/download_components.py`) — downloads raw NetCDF files from Box for each PM2.5 component
3. **Aggregate single component** (`src/aggregate_components.py`) — rasterizes polygons onto the NetCDF grid and computes area-weighted mean concentrations; outputs one intermediate Parquet per component per year
4. **Merge components** (`src/merge_components.py`) — joins all per-component intermediate files into a single wide-format Parquet per year

In the Snakemake pipeline, steps 3 and 4 correspond to the `aggregate_single_component` and `merge_components_{yearly,monthly}` rules.

# Configuration files

The configuration structure within the `/conf` folder allows you to modify the input parameters for the pipeline.

## Key parameters (in `conf/snakemake.yaml`):

* `version`: Algorithm version. Options: `V5NA`, `V6NA` (default). Controls data source and directory subtree.
* `temporal_freq`: List of temporal frequencies to process. Options: `yearly`, `monthly`.
* `polygon_name`: List of polygon types to aggregate into. Options: `zcta`, `county`.
* `shapefile_year`: List of shapefile boundary years to download.
* `components`: List of PM2.5 components to process. V6NA supports: `no3`, `so4`, `ss`, `nh4`, `dust`, `bc`, `om`. V5NA additionally supports `om_h2o`.
* `years`: List of data years to process (e.g. 2000–2023).

## Configuration files:

* `conf/snakemake.yaml`: Main pipeline configuration (version, years, components, polygon, temporal freq)
* `conf/config.yaml`: Hydra base config for running scripts directly
* `conf/satellite_component/us_components_v5na.yaml`: V5NA component Box URLs, file prefixes, and layer names
* `conf/satellite_component/us_components_v6na.yaml`: V6NA component Box URLs, file prefixes, and layer names
* `conf/shapefiles/shapefiles.yaml`: Census shapefile URLs by polygon type and year
* `conf/datapaths/cannon_v5na.yaml`: FASRC absolute paths for V5NA
* `conf/datapaths/cannon_v6na.yaml`: FASRC absolute paths for V6NA

## Version-based directory layout:

All input, intermediate, and output data is segregated by version:

```
{base_path}/
├── input/
│   └── components/
│       ├── V5NA/{temporal_freq}/{component}/          ← V5NA raw NetCDF files (flat)
│       └── V6NA/{temporal_freq}/{component}/{year}/   ← V6NA raw NetCDF files (year subfolders for monthly)
├── intermediate/
│   ├── V5NA/{temporal_freq}/{component}/              ← per-component parquet
│   └── V6NA/{temporal_freq}/{component}/
└── output/
    ├── V5NA/{polygon_name}_{temporal_freq}/           ← merged output parquet
    └── V6NA/{polygon_name}_{temporal_freq}/
```

# Run

## Conda environment

Clone the repository and create a conda environment.

```bash
git clone <https://github.com/<user>/repo>
cd <repo>

conda env create -f environment.yaml
conda activate <env_name>   # environment name as found in environment.yaml
```

It is also possible to use `mamba`.

```bash
mamba env create -f environment.yaml
mamba activate <env_name>
```

## Input and output paths

```bash
python utils/create_dir_paths.py
```

Pass the version-specific datapaths config if needed:

```bash
python utils/create_dir_paths.py datapaths=cannon_v6na   # V6NA (default)
python utils/create_dir_paths.py datapaths=cannon_v5na   # V5NA
```

## Pipeline

You can run the pipeline steps manually or via Snakemake.

**Run pipeline steps manually (V6NA — default)**

```bash
# 1. Download shapefiles
python src/download_shapefile.py polygon_name=zcta shapefile_year=2020

# 2. Download a component
python src/download_components.py satellite_component=us_components_v6na component=no3 ++temporal_freq=yearly ++version=V6NA

# 3. Aggregate a single component (repeat for each component)
export PYTHONPATH=.
python src/aggregate_components.py satellite_component=us_components_v6na polygon_name=zcta ++temporal_freq=yearly ++year=2020 ++version=V6NA ++component=no3

# 4. Merge all components into one output file
python src/merge_components.py satellite_component=us_components_v6na polygon_name=zcta ++temporal_freq=yearly ++year=2020 ++version=V6NA
```

**Run pipeline steps manually (V5NA)**

```bash
# 1. Download shapefiles
python src/download_shapefile.py polygon_name=zcta shapefile_year=2020

# 2. Download a component
python src/download_components.py satellite_component=us_components_v5na component=no3 ++temporal_freq=yearly ++version=V5NA

# 3. Aggregate a single component
export PYTHONPATH=.
python src/aggregate_components.py satellite_component=us_components_v5na polygon_name=zcta ++temporal_freq=yearly ++year=2020 ++version=V5NA ++component=no3

# 4. Merge all components
python src/merge_components.py satellite_component=us_components_v5na polygon_name=zcta ++temporal_freq=yearly ++year=2020 ++version=V5NA
```

**Run Snakemake pipeline (V6NA — default)**

```bash
snakemake --cores 4
```

**Run Snakemake pipeline (V5NA)**

```bash
snakemake --cores 4 -C version=V5NA
```

For SLURM environments, use the provided batch script:

```bash
sbatch snakefile.sbatch
```

Modify `conf/snakemake.yaml` to change `version`, `polygon_name`, `temporal_freq`, `components`, and `years` as needed.

## Dockerized Pipeline

**Note**: The Docker configuration predates the multi-step (aggregate + merge) pipeline and may require updates before use.

Create the folder where you would like to store the output dataset.

```bash
mkdir <path>/satellite_pm25_components_raster2polygon
```

### Pull and Run:

```bash
docker pull nsaph/satellite_pm25_components_raster2polygon
docker run -v <path>/input/components/yearly:/app/data/input/components/yearly -v <path>/satellite_pm25_components_raster2polygon/:/app/data/output nsaph/satellite_pm25_components_raster2polygon
```

If you are interested in storing the input raw and intermediate data run

```bash
docker run -v <path>/satellite_pm25_components_raster2polygon/:/app/data/ nsaph/satellite_pm25_components_raster2polygon
```

If you want to build your own image use
```
docker build -t <image_name> .
```

For multiplatform use
```
docker buildx build --platform linux/amd64,linux/arm64 -t <username>/<image_name>:<tag> . --push
```
